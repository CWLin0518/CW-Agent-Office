已拍板決策

7 項決策已定案 2026-08-22
1 第 1 節連線語意
✓ 兩者都要（authored + derived）
落地方式：derived 先在 P4 做，authored 排到 P4.5。derived 連線資料來源既有、風險低；authored 連線牽涉存取控制與使用者互動設計。
2 第 2 節外部路徑是否跨機器同步
✓ 不用，本機路徑就好
外部 Agent 路徑只需支援本機檔案系統路徑，不做跨機器同步或雲端功能。簡化設計範圍，現階段不支援分散式共享。
3 第 3 節 17 類權限 Phase B 優先度
✓ 不急，按順序開發
Phase B（Network / Tool / Database / Secrets 等）不需要為特定類別插隊。按文件裡判斷的順序開發即可。Phase A 五類優先實裝。
4 與 PRD 對齊（Runtime Snapshot/Lifecycle State）
✓ 採方案 (a)，P0 先對齊
P4（agent-canvas）動工前，P0 階段先花一輪對照 `AGENT_RUNTIME_UPGRADE_PRD.md` 的 Runtime Snapshot/Lifecycle State 雛形。結論記錄下來再動工，不刻意繞開。
5 第 2 節 Agent Definition/Instance 雙層架構
✓ 不做，採較小方案
v1 在 `AgentProfile` 加 `external_template_path` 欄位即可。不做正式的雙層架構。之後如果發現需要範本版本管理、多專案分享等需求，再另外評估演化。
6 第 5 節外部 Provider 防護程度
✓ v1 做版本鎖，簽名先留白
v1 就做版本鎖（content hash 比對 + 檔案有變時強制 preview/confirm）。完整簽章驗證因需先決定金鑰/信任模型，schema 先保留欄位，不在 v1 做驗證邏輯。
7 第 2 節跨 Workspace 執行位置
✓ 不存在跨 workspace 執行
Agent 一律在使用者目前所在的 workspace 內建立與執行。不新建承接用的 workspace，也不需要 local bridge 做跨 workspace 轉發。「我在哪個專案的介面，Agent 就在那個介面」。
