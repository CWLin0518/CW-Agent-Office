## 1. 這階段做了什麼

P4.5 要做三件事（見 04 章節 §1、§8「P4.5」列、§9 決策 1）：

1. **手畫 authored 連線**：使用者在畫布上宣告「這兩個 Agent 允許互相溝通」，後端要真的拿這條線做存取控制。
2. **畫布上建立 subagent**：右鍵節點可建立以它為 parent 的新 Agent。
3. **P3 的 Agent 權限開關升級成依 edge 授權**：`gto send` 從「總是放行」變成「只放行到有 authored edge 的對象」。

開發過程中使用者又追加了兩輪需求（互動風格改成 Grasshopper 端點拖拉、derived 連線的清除/隱藏），一併記在下面。

### 1.1 後端（Rust）

| 項目 | 內容 |
|---|---|
| Authored 連線 CRUD | `AgentLinkRepository` 新增 `create_authored_link` / `delete_authored_link` / `has_authored_edge`（`crates/gt-agent/src/repository.rs`、`crates/gt-storage/src/agent_repository.rs`）。三者都是**無方向**的：畫 A→B 或 B→A 視為同一條線，避免重複拉線造成「刪了一條，另一條還在」的授權漏洞（第一輪 code review 的 Critical，已修）。 |
| Derived 連線清除 | 新增 `delete_derived_link`，**方向性**刪除（跟 authored 相反——A→B 和 B→A 是各自獨立的往來事實，不是同一組關係）。清掉的只是畫面顯示，之後這兩個 Agent 若又真的 `gto send`，線會自動重新出現。 |
| Subagent 建立 | `commands/agent.rs` 的 `AgentCreateRequest` 新增 `parent_agent_id`；建立前會確認 parent 存在、且 parent 的 `allow_subagent_spawn` 政策允許，檢查放在任何有副作用的動作（讀外部範本、寫 prompt 檔）之前，被拒絕不會留下半成品 Agent。 |
| Edge 授權升級 | `local_bridge.rs` 的 `ensure_agent_allowed_to_dispatch`：`allow_gto_send=false` 仍然無條件拒絕；`true` 時，改成對 `task.dispatch_batch` 的每個 target 都要求存在 authored edge，沒有就拒絕（`AGENT_POLICY_EDGE_REQUIRED`）。sender 對自己派發（自己也在 targets 裡）會跳過檢查，避免誤擋。 |
| Tauri command | `commands/agent_canvas.rs` 新增 `agent_canvas_create_authored_link`、`agent_canvas_delete_authored_link`、`agent_canvas_delete_derived_link`，都已在 `lib.rs` 註冊。 |

### 1.2 前端（React / TypeScript）

| 項目 | 內容 |
|---|---|
| Grasshopper 風格端點連線 | 每個節點左右各一個 input/output 端點（`AgentCanvasNodeCard.tsx`），直接拖拉端點到端點建立連線；拖拉放開時按住 **Shift** 是取消連接（同一手勢反轉語意）；端點右鍵有「取消連接」（清掉該端點所有連線）；連線本身右鍵可單條刪除。實作在 `AgentCanvasPane.tsx`，用 pointer capture + `document.elementFromPoint` 做拖放偵測，`position: fixed` 的螢幕座標 SVG 畫拖曳中的預覽線。 |
| Subagent 節點縮小 | 共用畫布引擎 `components/graph-canvas` 的 `GraphCanvasNode` 新增可選的 per-node `width`/`height`，subagent（`parent_agent_id` 有值）用比較小的尺寸渲染，對其他呼叫方（例如 business-designer）完全不影響（沒設定就退回原本的統一尺寸）。 |
| 連線視覺 | 三種連線（authored 實線／derived 虛線／ownership 點線）都改用同一個「輸出端右側 → 輸入端左側」的 Grasshopper 式貝茲曲線（`computePortEdgeGeometry`），取代共用引擎原本「就近取邊」的通用算法。 |
| Derived 連線管理 | 右鍵 derived（自動產生）連線可「清除這筆記錄」；畫布控制列新增顯示/隱藏 derived 連線的切換鈕（純前端渲染過濾，不動資料庫）。 |
| Subagent 建立入口 | 右鍵節點的「新增 Subagent」會開啟既有的 `StationManageModal`（不是重寫一個簡化表單），透過 `useShellRootController.tsx` 既有的狀態組裝模式傳入 `parentAgentId`，在 `addStation`/`updateStation` 的每個關閉路徑都會重置，避免舊的 parent 內容誤繼承到下一次建立。 |

## 2. Code Review 記錄

依使用者要求，每輪都用 `林家維/2_Agents/BIM Agents/code-reviewer.md` 這份 persona 餵給一個 subagent 做審查（五維度：正確性/可讀性/架構/安全/效能）。逐條記錄見 `docs/kanban/index.html` P4.5 卡片，這裡只列結論：

**第一輪（後端授權模型 + 最初的點選式連線 UI）**
- Critical①：authored 連線唯一鍵有方向性、但查詢/產品語意無方向 → 已修（見上表）。
- Critical②：新的 edge 授權只接在 `task.dispatch_batch`，`channel.publish`（MCP 側車工具 `gto_handover`/`gto_report_status` 走這條路）完全沒有等效檢查 → **這是 P3 就存在的既有缺口，這次沒有擴大範圍去補**，只把畫布提示文案改成精確描述「`gto send` 批次派發」，避免誤導使用者以為所有溝通管道都被擋住。**這是目前最大的已知殘留缺口，見第 3 節。**
- Important：agent 對自己派發原本會被誤擋（已白名單）；`pendingSubagentParentId` 補上重置。

**第二輪（互動改成 Grasshopper 端點拖拉之後）**
- Important①：拖曳預覽線起點只在按下當下算一次，中途縮放會脫節 → 已改成每次 pointermove 即時重算。
- Important②：三種連線都漏接了引擎的 `arrowMarkerUrl`，方向箭頭消失 → 已補回 authored/derived 兩種連線的 `markerEnd`。
- Suggestion：Esc 取消拖拉時沒有明確 release pointer capture → 已補上（跨平台 WebView 保險）。

**真人操作抓到的執行期 bug（非 code review）**
- `handlePortPointerMove` 在 `setWireDrag` 的 updater function 裡才讀 `event.currentTarget`，但 React 合成事件的 `currentTarget` 在 handler 同步執行完就會變成 `null`（符合原生 DOM 事件規範，不是 React 特有的 pooling 問題），updater 卻是延後呼叫的 → 拖曳端點移動滑鼠時就會噴 `Cannot read properties of null (reading 'getBoundingClientRect')`。已修成在 handler 內同步算好座標，updater 只單純合併 state。

## 3. 已知殘留缺口 / 需要決策的事

1. **`channel.publish` 沒有 edge 授權檢查**（見上）。`gto_handover`／`gto_report_status` 這兩個 MCP 側車工具目前仍可以在沒有 authored edge 的情況下把任務內容送到另一個 Agent 的 inbox。要不要把這個路徑也接上 edge 檢查，是一個需要另外決定範圍的題目（牽涉到要不要把 Phase A「Agent」權限類別的範圍正式擴大到 `channel.publish`），這次刻意沒有動它。
2. **Rust 自動化測試覆蓋不完整**：`local_bridge.rs` 的 edge 授權邏輯、`commands/agent.rs` 的 parent 政策檢查，都因為專案裡一大批既有測試檔（`local_bridge_tests.rs`、`commands/tests/agent_tests.rs`、`commands/tests/workspace_tests.rs`、`tests/app_state_tests.rs`、`channel_adapter_tests.rs`、`gt-task/tests/lib_tests.rs`）已經引用了一個被移除的 roles/departments 子系統、目前整批編譯不過（**這是這次 P4.5 之前就存在的技術債，跟這次改動無關**），導致新增的測試「已確認能編譯，但無法用 `cargo test` 實際跑」。`gt-storage`/`gt-agent` 這兩個 crate 的測試（authored/derived link 的各種案例，共 13 個）不受影響，全部正常跑且通過。
3. **真人操作驗收尚未跑完整輪**：目前只有使用者在測試端點拖拉時意外撞到一次執行期 bug（已修）。完整的操作驗收清單（見第 4 節）還沒有人跑過一遍。

## 4. 建議的驗收清單

在桌面 App 裡手動測試：

- [ ] 從一個節點的 output 端點拖到另一個節點的 input 端點，確認建立 authored 連線（實線）
- [ ] 對已連線的兩個端點再拖一次、放開時按住 Shift，確認連線被移除
- [ ] 右鍵一個端點，確認「取消連接」會清掉該端點上所有連線
- [ ] 右鍵一條 authored 連線本身，確認可以單條刪除
- [ ] 讓兩個 Agent 真的 `gto send` 一次，確認畫布上出現 derived 虛線；右鍵該線確認「清除這筆記錄」能讓線消失，再送一次 `gto send` 確認線會重新出現
- [ ] 畫布控制列的顯示/隱藏切換鈕，確認能整批隱藏/顯示 derived 連線
- [ ] 右鍵節點「新增 Subagent」，確認建立出來的節點比一般節點小、`parent_agent_id` 正確指向被點的節點
- [ ] 沒有畫線的兩個 Agent 之間嘗試 `gto send`，確認被拒絕（`AGENT_POLICY_EDGE_REQUIRED`）；畫線之後再送一次，確認放行
- [ ] 把 parent 的 `allow_subagent_spawn` 政策關掉，確認在它底下建立 subagent 會被拒絕
