## 4. 已知殘留缺口（不需要立即決策，但記錄下來）

1. **真人操作驗收尚未跑**：已用打包好的 release build（`npm run build:tauri`）實際啟動桌面 App 並截圖確認能開機、主畫面正常渲染（讀取到真實 workspace 資料、無白屏無 crash），但**沒有**自動化點擊進「能力」分頁做端對端驗證——這個環境沒有現成的 Tauri/WebView2 UI 自動化工具（`run` skill 檢查過，Electron 的 Playwright `_electron` 驅動不適用於 Tauri），而且視窗裡是使用者真實在用的 workspace，盲點座標亂點有動到真實資料的風險，確認能開機後就停手了。第 5 節的清單目前只靠自動化檢查（型別檢查、lint、後端測試）跟程式碼審查驗證過。
2. **Hook 目前只支援 `type: "command"`**：Claude Code 的 hooks schema 其實還有 `type: "prompt"`（prompt-based hook，讓模型自己判斷 allow/deny）跟 `timeout` 欄位（CLI 內附的 `validate-hook-schema.sh` 有驗證這兩者），這次的 `HookCapability`/`build_settings_json` 沒有涵蓋，只做了 08 文件描述的最小必要欄位（event/matcher/command）。
3. **`-p` profile 疊加的驗證停在語法層**：實測驗證到「`codex -p <profile> mcp list` 會列出疊加後的 server」跟「`-p` 放在 `resume`/`fork` 前面能正確解析（`--help` exit code 0）」，但沒有驗證到一次真正互動的 `resume`/`fork` session 裡，profile 裡的 MCP server 真的被模型呼叫成功——這需要一次會消耗真實 API 額度的端對端測試，目前還沒做。
4. **多 workspace 節點顏色／連線等既有 P4.5/P4.6 缺口**：與此次改動無關，狀態不變，細節見 `docs/cw/06_P4.5開發進度.md` §3、`docs/cw/07_P4.6開發進度.md` §3。
