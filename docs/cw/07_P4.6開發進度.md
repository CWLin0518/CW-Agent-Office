- Suggestion：`isValidInstance` 沒有驗證 `position` 的形狀，手動修改過的 localStorage 可能塞入 `NaN` → 已修，補上 `Number.isFinite` 檢查。

## 3. 已知殘留缺口 / 需要決策的事

1. **P4.5 §3 提到的既有缺口**（`channel.publish` 沒有 edge 授權檢查、Rust 測試套件因為既有技術債編譯不過）本階段沒有觸碰，狀態不變，細節見 `docs/cw/06_P4.5開發進度.md` §3。
2. **多 instance 的「主要 instance」錨定是刻意的取捨**：一個 agent 有多個畫布節點時，authored/derived/ownership 連線只會畫在其中一個（陣列裡最早出現的）節點上，不會每個 instance 都各畫一條。這是配合「每個後端連線 row 對應剛好一條畫面上的線」這個不變量的犧牲，考量到功能⑧本來就明講是「純視覺關係」，可以接受，但如果之後有人想要「每個 instance 都要看到自己的連線」，這是需要重新設計的地方。
3. **多 instance 的節點擺放不會跨重啟持久化**：只有每個 agent的「預設 instance」（`instanceId === agentId`）位置會存到後端；使用者從備用列多拖出來的節點，重開 App 後會消失，只留下預設節點。這是使用者已經確認過的決策（純前端），不是 bug。
4. **左側備用列目前只能用滑鼠拖拉**：沒有鍵盤可達的替代路徑（跟這個 pane 既有的 wire 拖曳手法一致，都是 pointer-only），如果之後要做無障礙優化，這是待補項目。
5. **真人操作驗收尚未跑**：以下第 4 節的清單目前只靠自動化檢查（型別檢查、lint、後端測試）跟程式碼審查驗證過，還沒有人在桌面 App 裡實際跑過一遍。
