# docs/cw — 專案架構 SPEC

這個資料夾是給第一次做軟體開發的你準備的架構說明文件。目的是把 GT Office 目前的前端、後端架構講清楚，讓你之後要重新設計「Agent 建立方式」「UI」「操作/協作機制」時，知道自己站在什麼樣的地基上、哪些東西可以直接沿用、哪些東西要改。

這份文件只描述**現狀**（現在的程式碼長什麼樣），不包含你未來想做的客製化設計。等你想清楚要怎麼改，我們會另外開一份設計文件（例如 `docs/cw/04_客製化設計.md`）來記錄新的方向，不會混在這份 SPEC 裡。

## 適合誰讀

你說這是第一次做軟體開發，所以這幾份文件會：

- 先用白話解釋名詞，再進到實際目錄結構
- 盡量用「這個資料夾/檔案負責做什麼」的方式描述，而不是丟一堆術語
- 每個結論都對應到實際存在的檔案路徑，你可以自己打開來對照

## 名詞速查表

| 名詞 | 白話解釋 |
|---|---|
| 前端 (Frontend) | 使用者看到、點擊、輸入的畫面部分。這裡用 React + TypeScript 寫，跑在 Tauri 包好的視窗裡。 |
| 後端 (Backend) | 不直接顯示畫面，但負責「真正做事」的部分：讀寫檔案、開終端機、跑 Git 指令、存資料庫。這裡用 Rust 寫。 |
| Tauri | 一個把「網頁前端」包裝成「桌面應用程式」的框架。前端還是網頁技術，但可以透過 Tauri 呼叫 Rust 後端、存取檔案系統，不像純網頁那樣被瀏覽器關住。 |
| IPC / invoke | 前端呼叫後端函式的方式，類似前端喊一聲「幫我做這件事」，後端回應「做完了，結果給你」。 |
| Event | 後端主動推消息給前端，不需要前端先問。例如終端機有新的輸出文字，後端會主動推給前端顯示。 |
| PTY | 一個「假的終端機」，讓 Rust 後端可以像真的開一個 terminal 一樣去跑 `claude`、`codex` 這些 CLI 指令，並把畫面截取出來給前端顯示。 |
| Crate | Rust 的「套件」單位，一個 crate 大約等於一個獨立的功能模組（資料夾），例如 `gt-git` 專門處理 Git 操作。 |
| Monorepo | 一個 Git 倉庫裡放了多個專案（前端 app、後端 app、共用套件），而不是每個專案各開一個倉庫。 |
| Workspace (在這個專案的語境) | 使用者打開的一個工作目錄（例如一個 Git repo 資料夾）。所有檔案、終端機、Git 操作都綁定在某個 workspace 底下，不能跨出去。 |
| Station | 工作台上的一張卡片，代表一個正在跑的 Agent（例如一個 Claude Code 或 Codex 的終端機）。 |
| Agent | 這裡指的是像 Claude Code、Codex CLI 這樣的 AI coding agent，在 Station 裡面被啟動、執行任務。 |
